# IdleWars：项目约定

单文件网页战棋，**界面和文案只有中文**，无后端、无构建工具。`src/` 是拆并的源文件，`build.sh` 拼成 `idlewars.html`（整页，约 5500 行，直接用浏览器打开就能玩）。

完整资料在 `.claude/docs/`：
- `design.md`：规则、界面、改动时间线、已知问题（设计与改动记录，截至 v400）。
- `rules.md`：规则书，按玩家视角写的完整规则（截至 v400）。
- `handoff.md`：代码地图、核心流程、动画约定、测试写法、踩过的坑、下一步建议。**动手前先读它。**

## 和用户合作的习惯（请照做）

- 用**中文**回复，一行一句，别写长文字；弹窗、按钮、状态栏的文案也要短。
- 小而明确的要求直接做；大的或有歧义的**先确认理解**再动手；拿不准就问，别猜。
- **如实说验证了什么、没验证什么**：自动测试通过不等于看过画面，没亲眼看的要直说。
- 用户会在你工作中途发来补充或纠正，**每一条都要处理，不能漏**。
- 回复结尾问“还有别的要改吗？”。
- 这是偏**视觉演示**的战棋，动画和状态提示很重要，不能为省事去掉。
- 不要自作主张加速、合并、简化。用户明确要求过：每一步都按设置里的“电脑每步停留”播放，不准自动加速；新兵一律新建兵团、不自动补进旧兵团。
- 设计取向：**简单优先，不求写实**；玩家只做决定（下命令、造兵、设补给），其余全部由程序自动完成；新规则先提最简单的版本。
- 按钮颜色约定：返回/继续用绿，保留命令用橙，清空/放弃命令用红。
- 讨论过先不做的：**编组下令**（一批兵团一起下令，整批只花 1 点指挥点）。要做先问用户。
- 提交直接推 `main`，**不要开 PR**（用户嫌烦）。提交信息用中文，一次改动一条。

## 日常工作流

1. 改 `src/` 里的文件（一次改一小块，别用批量替换；替换前确认锚点只出现一次）。
2. `./build.sh`：拼成 `idlewars.html` 并做语法检查，要看到 `SYNTAX_OK`。
3. 跑回归：第一次先 `npm install`（只装 playwright 模块），然后 `npm test`，会先拼装，再依次跑 `all_panels`、`save_load`、`clearing_sim` 三个，要全部写“通过”。再按改动单独跑专项，一次只跑一个，用 `timeout` 包住：`node tests/xxx.js $PWD/idlewars.html`。
4. 改了用户可见的东西，`src/page.html` 里的版本号 `<small class="ver">vNNN</small>` 加 1。
5. 用户说“更新一波文档”时，更新 `.claude/docs/design.md`（改动时间线、规则、已知问题）；规则有变就同步改 `.claude/docs/rules.md`（规则书），以代码为准。

## 几条硬规矩

- 改了状态就要调 `touch()`（`G.ver++`），缓存靠它失效。
- 新增一个设置要改四处：`DEFAULTS`、`applyParams`、`readForm`（漏了会在开新游戏时被丢）、参数窗口。
- 所有中文文案在 `src/text.js`，用 `tr('key')` 取；改词前先全文搜，同一概念常在帮助、战报、弹窗里各写一遍。
- 隐藏控件 `#sSpeed` 只给自动测试用，不要重新暴露给用户。
- 临时把状态换掉再算东西（如 `supplyViz`）必须 `try/finally` 换回来。
